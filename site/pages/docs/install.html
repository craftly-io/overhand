Three ways in. Pick one.

  • One command Installs, starts {{name}} at every login and opens it in your browser. 
    {{install}}
  • Homebrew The same package, checked against the same release sums. 
    brew install craftly-io/tap/overhand && overhand start
  • npx or bunx The first run fetches this version's package once and keeps it in ~/.overhand/npm. 
    npx overhand start    # or: bunx overhand start

What the installer does.

  • Checks the download It fetches the package for your machine (macOS or Linux, arm64 or x64) and stops if its SHA-256 doesn't match the release's SHA256SUMS.
  • One folder, one link Each version unpacks into its own folder in ~/.overhand/releases, and ~/.overhand/app links to the one in use. overhand is linked into ~/.local/bin. Everything {{name}} keeps lives under ~/.overhand.
  • The right build In a Rosetta terminal on an Apple silicon Mac it still picks the arm64 build. On Alpine and other musl Linux systems it stops and says so: the Linux builds need glibc.
  • Your PATH When ~/.local/bin isn't on it, the installer prints the exact line for your shell and the file to put it in.
  • Then it opens {{name}} answers on {{localUrl}}, where setup finishes. Set OVERHAND_NO_START=1 to install without starting it.

What else it needs.

  • git and the GitHub CLI Agents read issues and open pull requests through gh, signed in with gh auth login.
  • At least one agent Any of {{agents}}, installed and signed in. Setup can install one for you in a terminal you watch.
  • A quick check overhand doctor lists each thing it needs and how to fix what's missing. See Troubleshooting.

On Linux.

  • A systemd user service {{name}} runs as one; systemctl --user status overhand shows it. Without systemd (a container, WSL) it runs in the background until the machine restarts.
  • Desktop notifications Through notify-send, when it's installed.
  • On a server systemd stops your services when you log out. To keep {{name}} running and start it at boot, turn on linger once (the installer prints this when it's off): 
    sudo loginctl enable-linger "$USER"
  • Secrets They go to the keyring through secret-tool (sudo apt install libsecret-tools), which a desktop session unlocks. With no keyring, saving a secret fails and says so: {{name}} never quietly writes one to disk. To opt in to a file only you can read (mode 0600, as gh and claude do there), add the first line to your shell's startup file: 
    export OVERHAND_SECRETS_FILE=~/.overhand/secrets.json
overhand stop && overhand start

Update.

  • It tells you Once a day {{name}} looks for a new release on GitHub, and Needs you shows the command for the way you installed.
  • One command overhand update reruns the installer, runs brew upgrade overhand, or for npx is npx overhand@latest update. It prints the version it installed and restarts on it once no agent is running.
  • All or nothing The new version is downloaded, checked and unpacked beside the one in use, then swapped in at once. If any step fails, it says so, exits with an error, and the installed {{name}} is unchanged.
  • Your own brew upgrade or installer run Works too. The login service runs the binary through a path that follows updates, so a running {{name}} restarts on the new version by itself.

Uninstall.

  • One command Stops {{name}}, removes its login service (the launch agent on macOS, the systemd unit on Linux), the ~/.local/bin/overhand link and the program in ~/.overhand, then lists what it kept. 
    overhand uninstall --dry-run   # see what it removes and keeps
overhand uninstall
  • Your data stays Settings, history and logs in ~/.overhand are kept. To delete them too, add --remove-data; it asks before deleting anything.
  • Also kept Secrets in Keychain or the keyring, and the hooks overhand connect wrote into projects. Run overhand disconnect in each connected project before you uninstall.
  • Homebrew Run overhand uninstall, then brew uninstall overhand.
  • npx or bunx npx overhand uninstall removes the service and the copy in ~/.overhand/npm.
