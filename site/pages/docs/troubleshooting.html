Start with these.

  • overhand doctor Each thing {{name}} needs, ticked or crossed, with the fix under every cross. It exits non-zero while something required is missing.
  • overhand status Whether it's running, on which port and version, its last heartbeat, agents at work and free disk.
  • overhand logs -f Follows its log; without -f, the last lines.
  • Needs you {{name}} also checks itself every quarter of an hour, and a problem it finds shows there. Every problem there comes with its fix as a button: one that fixes it, or opens exactly where the fix is. A red line under the story opens its ticket or its lead.

Installing.

  • Checksum mismatch for The download didn't match the release's sums, so nothing was installed. Run the installer again; if it repeats, tell us.
  • Download failed: The release files couldn't be reached from here. Check the connection, or a proxy in the way.
  • Overhand runs on macOS and Linux; this is There's no package for this system.
  • isn't installed yet; the setup page shows how to get it. git is missing, or gh and the installer found no way to install it here. Install it; {{name}} itself is installed.
  • needs an administrator to install Installing gh on Linux takes sudo, which would ask for a password. Run the command it printed; the setup page goes on by itself.
  • Overhand didn't start. The lines above it say why; overhand logs has the rest.

Running.

  • is in use; is Overhand already running? (overhand status) Something already listens on {{name}}'s port, often {{name}} itself. overhand status says which.
  • One Overhand per folder: stop that one first Another {{name}} already works from the same state folder, on the port the message names. Two would take the same task into one worktree. Stop it with overhand stop, or give each copy its own OVERHAND_HOME.
  • doesn't load, so Overhand runs on the last copy that did Your config file was cut short or edited into something that isn't valid JSON. {{name}} keeps the last copy that loaded: Restore in Needs you puts it back, or fix the file and {{name}} takes it in by itself.
  • has settings Overhand doesn't know A name in your config file is misspelt or no longer used, so it does nothing. Fix or remove the names the card lists.
  • Overhand isn't running (nothing answers on port Start it with overhand start.
  • Overhand didn't come up on port It started but never answered. The message names its log; read it with overhand logs.
  • No daemon log yet at The log appears once the login service has run; overhand start sets it up.
  • Not set up yet: run Setup counts as finished only once you press Start on its last step; saving Settings before that doesn't. Run the command it names (overhand open while {{name}} runs) and finish setup in the browser.

Accounts and tools.

  • agents open pull requests and read issues through it The GitHub CLI isn't signed in. Press Sign in to GitHub on the setup page or in Health, or run gh auth login yourself.
  • doesn't look like an Anthropic API key The stored key isn't one; store a key from platform.claude.com again.
  • nothing answers there: start the gateway or fix its URL A gateway account's address gives no answer: start the gateway, or fix its URL in Settings.
  • Tailscale isn't running on this Mac. Open Tailscale and sign in, then try Settings → Phone again.
  • Saving a secret fails on Linux There's no unlocked keyring. See On Linux.

A run that stopped.

  • Its card says why A task whose run stopped shows in Needs you, marked stopped, with one sentence for the reason and the button that fixes it. What the agent printed waits under Details.
  • {{w.signInRetry}} Runs the same task again, with its brief and its branch: nothing done so far is lost.
  • {{w.failedMoreDetail}} When the agent changed nothing, it isn't run again on its own. Say more about what you want and it starts again from that.
  • {{w.failedReopen}} The branch was pushed, but GitHub didn't answer when its pull request was opened. This only opens the pull request; nothing runs again.
  • {{w.stopLead}} Every agent working in the cast has one. It ends the run and everything it started, such as a dev server; its edits stay in its worktree, and the next run on that task is told they're there.
  • The time limit Counts only the time the computer was awake, so a laptop that slept through a run's limit doesn't stop it the moment it wakes. A run past its limit stops with everything it started, and its card says so.
  • A fix round that failed Another runs on the next pass, up to {{cfg.limits.maxFixes}} rounds; then the pull request waits for you.

Something not answering.

  • Can't reach Overhand. The page gets no answer, or none in 10 seconds when {{name}} is asleep or stuck. If it stopped, start it with overhand start on its computer; {{w.retryNow}} asks again at once.
  • The network or the tracker isn't answering A tracker that doesn't answer is read again every few minutes; {{w.retryNow}} asks at once.
  • asks Overhand to slow down The tracker limits how often {{name}} may ask. It waits and asks again on its own; {{w.alTrackerLimitGo}} hides the card meanwhile.
  • Its sign-in no longer works {{w.alTrackerFix}} opens the project's connections, where you sign in again.
  • Overhand tries again every pass GitHub didn't answer when {{name}} read a pull request. It says so once, reads it again every pass, and says when it reads again.

Updating.

  • The update didn't install; Overhand is unchanged. The line above it says why (no network, a checksum that didn't match, a full disk). The message ends with the command to update by hand for the way you installed.
  • This Linux uses musl Alpine and other musl systems can't run the Linux builds. Use a glibc system such as Debian or Ubuntu.
  • From the app When a new version is out, Needs you offers {{w.confirmUpdateGo}}: it runs the same update as overhand update, then restarts once no agent is running.
  • Still on the old version It restarts on the new one once no agent is running. To restart now: overhand stop && overhand start.
