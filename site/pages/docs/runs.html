One program does the rounds.

  • The daemon It plans the day, runs each account's agent headless on tickets, supervises leads, reads checks, deploys and errors, and serves the dashboard.
  • One at a time per project One ticket run per project at a time, in parallel across projects.
  • Secrets In the macOS Keychain or the Linux keyring, or the file you opted in to with OVERHAND_SECRETS_FILE.

How each agent is run.

  • Verified A real run went end to end through {{name}}'s own arguments, environment, output parser and schema check: a ticket answer validated against the ticket schema, and an edit (create hello.txt) found on disk afterwards.
  • Flags checked Checked against the agent's own --help and docs only. Recorded output is in packages/core/test/fixtures/runtimes.
  • Claude Code Verified; the default and the reference. claude -p --output-format stream-json --json-schema … --permission-mode auto. Model: the account's backend (see Agents and accounts).
  • Codex Verified on 0.163.0 with Ollama qwen3:1.7b. codex exec --json --sandbox workspace-write -c sandbox_workspace_write.network_access=true --output-schema <file>. Model: -m; a gateway account adds --oss --local-provider ollama.
  • Cursor Agent Verified on 2026.01.23 with model auto. cursor-agent -p … --output-format json -f. Model: --model.
  • OpenCode Verified on 1.19.3 with Ollama qwen3:1.7b. opencode run --format json --auto. Model: -m provider/model, or a gateway account's model.
  • Aider Verified on 0.86.2 with Ollama (edits on llama3.1:8b, answers on qwen2.5-coder:7b). aider --message … --yes-always --no-pretty --no-gitignore. Model: --model (ollama_chat/…, or openai/… through --openai-api-base).
  • Gemini CLI Flags checked. gemini -p … -o json --approval-mode yolo --skip-trust. Model: -m.

What the real runs showed.

  • Codex's sandbox In workspace-write it blocks the network (a sandboxed git push fails with "Operation not permitted") and keeps .git read-only (a sandboxed git commit fails on .git/index.lock). {{name}} turns the network on and makes the project's git folder writable; a Codex run then committed and pushed to a git://127.0.0.1 remote.
  • Codex and the network Per Codex's config reference, the setting allows outbound network in general, so GitHub is reachable too (not tried).
  • Codex's schemas They go to --output-schema in OpenAI's strict form: closed objects, every property required, optional ones nullable. The nulls are dropped before validation.
  • Codex on a gateway It runs --oss against the gateway's URL. There Ollama enforces --output-schema on every model call, so the model can't call tools and never edits (it answered "done" without creating the file). Local runs are asked for JSON in the prompt instead.
  • Small local models are flaky qwen2.5-coder:7b writes tool calls as text, so it can't edit through Codex or OpenCode. qwen3:1.7b can, but sometimes mistypes a long path or wraps its answer, which {{name}}'s one retry usually fixes. Use the biggest coding model your machine runs well.
  • Aider Its edits and the JSON answer come in one reply. An edit it couldn't apply ("did not conform to the edit format") fails the run, even though Aider exits 0.
  • Aider leaves no trace No history files land in the project, and .aider* goes to .git/info/exclude instead of the project's .gitignore.
  • Cursor Agent On a free plan it only runs model auto ("Named models unavailable" otherwise).
  • Gemini CLI Not run: its cached login had expired, and an expired login opens a browser prompt and waits until the task timeout instead of failing. In an untrusted folder it also drops yolo ("Approval mode overridden to default"), so {{name}} passes --skip-trust.

Answers and output.

  • Checked answers Every answer is validated against its schema. A wrong one is retried once, with what was wrong.
  • Claude Code only Only Claude Code reports usage windows and takes the Slack inbox's MCP flags (Model Context Protocol, how an agent reaches other tools); the inbox skips accounts on other agents.
  • The live line "What is it doing" and a lead's log read each agent's own output: Claude Code's transcripts, Codex's and OpenCode's JSON events (commands, edits, what it said), Aider's last lines.
  • One object at the end Cursor Agent and Gemini CLI print one JSON object when they finish, so their line shows only the result.
  • Installed? overhand doctor checks each agent's command-line app in use is installed and shows its version.

What every run is told.

  • {{name}}'s agent instructions The ticket workflow, when to ask instead of guess, and the hard limits. They live in {{name}}'s own folder (~/.overhand/agent-home/claude-code/CLAUDE.md), never in your project.
  • How each agent gets them Claude Code reads them from its config folder. Codex gets -c developer_instructions=…, OpenCode instructions in its inline config, and Aider --read. Cursor Agent and Gemini CLI read rules only from the project, so they get them at the head of the prompt.
  • Your project's own instructions Each project's row in Crew (or the command bar) shows its CLAUDE.md, AGENTS.md, GEMINI.md and rules files as written, which agents read each one, and any gaps and contradictions.
  • A rule from review When review asks for the same thing on two pull requests within 30 days, and no instruction file says it yet, Needs you offers it as a rule. {{w.ruleAdd}} opens a small draft pull request adding it to the file the project's agent reads.

{{name}} as an MCP server.

  • overhand mcp {{name}}'s own MCP server over stdio. Any agent that speaks MCP can ask it what's running and what needs you, answer a lead's question, and hand or answer requests between sessions.
  • Its tools status (agents and leads at work, and the Needs you list as the dashboard words it), answer_lead, ask_session and ack_request. Each does what overhand answer, overhand ask and overhand ack do, through the running daemon.
  • In every run {{name}} adds it to each Claude Code run and lead it starts, and to runs on {{modeWatch}} too, where it's the only MCP server. Other agents don't get it yet.
  • A run's own key Inside a run the server calls the daemon with that run's key, so it does only what the run may: hand a request (one to your own session comes to you first), answer requests sent to it, and answer its own lead's question. It can't read the status, and no run answers a question as you.
  • In your own sessions Outside a run it uses this computer's local key, like the overhand command, so it acts as you. Add it to Claude Code with claude mcp add overhand -- overhand mcp; any other agent takes the same command as a stdio server.

The scorecard.

  • Every run is logged Its project, ticket, kind, account, agent, backend, model, cost at API prices (known costs only; a local model is $0) and outcome.
  • Each pull request's fate Merged or closed, fix rounds, change requests and time to merge, joined in from outcomes.jsonl. Older days are read back from the activity log.
  • The ranking Health's Scorecard ranks each agent × model over 7 or 30 days, overall and per project: runs, pull requests opened, merge rate, first-try merges, median time to merge, and why the rest didn't land.
  • Cost per merge Billed cost per merged pull request ("included in plan" on a plan), beside the API-price cost for comparison. Only pay-per-use and cloud runs count as billed.
  • Too few Under 5 runs reads "too few runs to tell".

Routing: what the scorecard changes.

  • routing.mode Set in the config; a new install has {{cfg.routing.mode}}.
  • suggest When another agent and model you've set up merges clearly more often on a project (both with 5+ runs, at least 1.5× and 15 points better), Needs you says so and opens that project's accounts. Nothing changes by itself.
  • auto Each new ticket runs on the project's allowed account (accounts, else all) that scores clearly best. While samples are thin it keeps today's order, and it moves to the next allowed account when one is cooling down or its agent or gateway doesn't answer.
  • Never spread It never spreads work over several accounts of the same agent and backend (your subscriptions), and leaves projects on {{modeWatch}} alone.
  • off Today's order.
