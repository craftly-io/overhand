Four modes, one per project.

  • {{modeWatch}} Agents plan, investigate and report on the ticket. They change no code and open no pull requests, and the guard blocks edits and commits.
  • {{modePropose}} Agents open draft pull requests and stop there. You review each one and mark it ready.
  • {{modeAct}} Agents open pull requests ready for review. Merging stays with you.
  • {{modeShip}} As {{modeAct}}, then GitHub's own auto-merge merges the pull request once every required check passes. No agent merges.

Choosing one.

  • Where Settings → Projects, under {{modeLabel}}.
  • Where it starts Every new project starts on {{modePropose}}.
  • Nothing merges without you On the first three modes, every merge is yours.

Turning on {{modeShip}}.

  • Your click, one project Never for a group of projects and never as a global switch. It works on GitHub only.
  • A required check first The base branch needs branch protection or a ruleset with at least one required status check; without one, the project keeps working as on {{modeAct}} and says why.
  • Its defaults Up to {{shipPerDay}} merges a day; changes to {{shipProtect}} wait for your merge. Both are per project.
  • Undo Every {{modeShip}} merge shows up in the day's log and the night report, with an Undo that opens a revert pull request.
  • All of its rules Ship's safety rules, under the hood.

How {{modeShip}} merges, step by step.

  • GitHub's auto-merge Once a pull request carries its proof, the daemon turns on auto-merge with the enablePullRequestAutoMerge mutation (squash). No agent's settings change.
  • Checked every time The required check is looked for again before every request. Without one, the project says {{w.shipNoGate}} and builds as on {{modeAct}}.
  • Config Protected paths are ship.protect; the daily cap is ship.perDay. A pull request held by either says so on the pull request.
  • Turned off again A request for changes, a push onto a protected path, or the project leaving {{modeShip}} turns auto-merge off.
  • Leads too A lead's pull requests take the same step: its run's checks go on the pull request as its proof. Auto-merge is on only while none of the project's leads is running.
  • Told everywhere Each merge is in the day's log, the night report and a push notification.
  • Undo, safely The revert pull request comes from a new branch: never a push to the base, never forced.

What {{name}} does itself, on every agent.

  • On {{modeWatch}} It never opens a pull request and runs no fix rounds. A finished ticket becomes a report on the ticket, which then waits for you.
  • On {{modePropose}} It opens pull requests with gh pr create --draft (on Bitbucket, draft: true).
  • The Review drawer Reads the diff with gh pr diff and marks drafts ready with gh pr ready. It approves with gh pr review --approve only when you aren't the author.
  • {{w.reviewRequestChanges}} Goes to the agent as its next fix round. You can also close the pull request there.
  • Old configs A config written before modes existed keeps acting.

What holds each agent on {{modeWatch}}.

  • Claude Code --permission-mode plan, plus overhand guard, which reads OVERHAND_AUTONOMY from the run's environment and blocks edits, commits, pushes and gh pr or issue writes.
  • Codex --sandbox read-only (no writes, no network), plus the guard.
  • Cursor Agent --mode plan, without -f, plus the guard.
  • OpenCode permission: { edit: "deny", bash: "deny" }, plus the guard.
  • Aider --chat-mode ask --no-auto-commits. It never runs shell commands.
  • Gemini CLI --approval-mode default: headless, nothing approves an edit or a command (flags checked only), plus the guard.
  • A lead on {{modeWatch}} It can't write its notes or questions file, so its final message is filed as a report in its questions file, and it waits for you.
  • A lead on {{modePropose}} Ticket runs never open pull requests themselves; {{name}} does, as drafts. Leads open their own. A Claude Code lead runs under the guard (through --settings), which refuses gh pr create without --draft, and gh pr ready. Leads on other agents are only instructed.
