A project agent looks after a whole project.

  • One agent, kept working One agent that works a whole project and asks you only what takes a person.
  • Asleep until there's work Each project agent wakes when its own kind of work shows up on its project, and works only on that.
  • Within the project's mode It goes only as far as the project's mode allows.
  • Kept running While a project agent is On, {{name}} restarts it after it exits, gives up after repeated crashes, and waits while its account is at its usage limit.
  • How often An always-on one starts again a few minutes after it exits, and rests longer each time it finds nothing to do, up to 4 hours. In Settings → Advanced → Project agent details, {{w.leadRestartLabel}} set to 1440 makes it run daily and 10080 weekly, and it rests that long.
  • Its accounts {{w.leadAccountsLabel}} lists them. At one's usage limit the next run takes the next; with {{w.leadFallbackLabel}} off, it never runs on another, and waits once all of them are used up.
  • When it can't start If a start fails before it runs, say an account missing its key, Needs you says why, with a button for that account and {{w.signInRetry}}.

How every project agent works.

  • Whatever its goal Every project agent's prompt, ready-made, generic or your own skill, carries the same lines, written once in {{name}}. {{wayOfWorking}}

When a project agent asks.

  • Under Needs you Answer in place, from your phone's notification, or from a terminal with overhand answer <lead> "your answer", naming the project agent by its key or label. --default goes with the default it gave.
  • From any terminal overhand answer goes through the running daemon, the same as answering on the dashboard. So your terminal session, or an agent's, can unblock a project agent it settled a question for. {{name}} never reads your other sessions.
  • Its default A question ends with what the agent will do if nobody answers. After the wait set for that agent (4 hours unless you change it in Settings → Advanced → Project agent details), {{name}} goes with it and tells you. A question with no default, or a wait of 0, waits for you.
  • Answered somewhere else {{w.answeredElsewhere}} resumes the agent when you settled it outside {{name}}.

Talk to a project agent.

  • Any time {{w.leadTalk}} in {{w.viewCrew}} opens a project agent's drawer: one conversation with it, and a box that's always there. Ask why something is the way it is, or tell it what to do from now on. With a question open, the same box answers it. It works the same from your phone, through Access from anywhere.
  • When it reads it The line under the box says which: at its next step (a Claude Code run takes it mid-run), when its run ends (any other agent), or {{name}} starts it to read it.
  • Its reply The run's last words come back as its reply, with a notification that carries none of its words. The newest five replies are kept.
  • Its limits stay A message is words in the agent's own file, nothing more: it keeps its project's mode, the guard and the sandbox, and its reply goes nowhere but the conversation. Only you send messages; an agent run can't, not even its own.
  • Agents on tasks To tell a running agent something, send its session a request under {{w.paneRequests}}; it's handed over at its next step and its answer shows there.

Your own project agent.

  • The generic one Add one in Settings → Advanced → Project agent details with no instruction of its own: it works the project's open issues and pull requests in priority order, with its notes kept in ~/.overhand, never in your project.
  • A project's own skill Point it at the skill, and have the skill keep a lock file and a questions file so {{name}} can supervise it. docs/leads.md has both formats and a snippet to paste.
