Clean up disk.

  • Where {{w.sweep}} in the actions menu, or {{w.machineFindSpace}} under Health → This machine.
  • You see it first A list of what can go, with sizes and when each was last used. Nothing is removed until you press the button, and each item is checked again just before it goes.
  • What it finds Caches, old versions of agent apps, agent apps nothing runs, local AI models and agent history long unused, Docker leftovers and old logs, finished and forgotten agent worktrees, and dependencies in worktrees that sat idle.
  • Never your work Nothing with uncommitted, untracked, unpushed or stashed changes, and never one of your own checkouts without asking.
  • From a terminal overhand cleanup plan lists, overhand cleanup run removes what's ticked.

Or let it run by itself.

  • Off until you choose Set cleanup.auto.schedule to daily or weekly. It then also cleans early when free disk runs low.
  • Only when idle It starts only while no agent or lead is running, and takes only the items safe to remove without you.
  • Low disk When space runs short, Needs you warns first; then heavy jobs wait, and then new agents and leads don't start.

Quiet mode: "I need my laptop".

  • What it does {{quietMode}} Edits and targeted tests carry on, and held work starts again when it ends.
  • Turn it on The Quiet mode row in the actions menu, or overhand quiet 3h (or 90m, up to 72 hours). overhand quiet off ends it.
  • Held anyway Heavy jobs also wait while the machine is busy, the battery is low, the Mac is throttling for heat, or disk is short.
  • From a script POST /api/quiet {"hours": 3} does the same. The header shows the time left.

What the cleanup looks at, in detail.

  • Finished worktrees Agent worktrees whose branch is merged or deleted on the remote, or whose pull request was merged or closed, when they're clean.
  • Idle dependencies node_modules and test artifacts (screenshots, test-results, reports) in agent worktrees idle {{cfg.cleanup.categories.worktrees.depsIdleDays}} days (cleanup.categories.worktrees.depsIdleDays). The agent reinstalls on its next run there.
  • Duplicate clones Full clones of a remote you already have, clean and fully pushed. They're listed unticked and go only when you confirm each one; worktrees of one clone are far cheaper.
  • Old simulators Simulator runtimes older than the newest per platform, listed unticked.
  • Measured, not guessed Freed space is the volume's free space before and after, since du overcounts APFS clones.
  • Disk thresholds Under {{cfg.governor.warnFreeGb}} GB free (governor.warnFreeGb) Needs you warns. Under {{cfg.governor.pauseHeavyBelowGb}} GB (governor.pauseHeavyBelowGb) heavy jobs wait. Under {{cfg.cleanup.minFreeGb}} GB (cleanup.minFreeGb) new agents and leads don't start.

Heavy jobs share the machine.

  • Why Several agents on one laptop can bury it with screenshot sweeps, full test suites and simulators at once.
  • Light work goes through The guard sorts every shell command. Edits, git, and a test run that names files or a test go straight through.
  • browser Playwright, Puppeteer, Lighthouse, axe, screenshot sweeps: {{cfg.governor.slots.browser}} at a time, up to {{cfg.governor.timeoutMin.browser}} minutes.
  • suite bun test, npm test, pytest, go test ./... with no file or name filter: {{cfg.governor.slots.suite}} at a time, up to {{cfg.governor.timeoutMin.suite}} minutes.
  • simulator xcodebuild, simctl boot, Maestro, Detox, expo run:ios: {{cfg.governor.slots.simulator}} at a time, up to {{cfg.governor.timeoutMin.simulator}} minutes.
  • build bun run build, next build, cargo build, docker build: {{cfg.governor.slots.build}} at a time, up to {{cfg.governor.timeoutMin.build}} minutes.
  • devserver bun run dev, next dev, expo start: {{cfg.governor.slots.devserver}} at a time, up to {{cfg.governor.timeoutMin.devserver}} minutes.
  • When it waits While the 1-minute load per core is over {{cfg.governor.maxLoadPerCore}}, on battery under {{cfg.governor.minBatteryPct}}%, while macOS reports thermal throttling, when disk is short, or in quiet mode.
  • What waiting means The agent is told why, and to do other work and retry. Each wait is logged in Health → Guardrails.
  • When it may start It runs inside overhand heavy <kind> -- <command>. Claude Code's hook rewrites the command; the other agents' hooks can't, so their agent is told to run the wrapped command itself.
  • The slot A lock file under slots/ holds the job's pid, so a slot whose holder died frees itself. Output passes straight through.
  • Stopped when stuck The job's whole process tree is killed past its limit, or after {{cfg.governor.silentMin}} minutes printing nothing.
  • Orphaned browsers Every minute the daemon stops headless browsers whose parent died and whose environment carries OVERHAND_RUN. Never your own.
  • Config All of it is governor in the config: slots, maxLoadPerCore, minBatteryPct, thermal, pauseHeavyBelowGb, warnFreeGb, timeoutMin, silentMin.
  • Protected processes governor.protect lists ports ({{name}}'s own {{cfg.governor.protect.ports}} by default), process names and Docker container name prefixes, for example {"ports": [4317, 4100], "containerPrefixes": ["demo-"]}.
  • What that blocks kill, pkill, killall, docker stop|rm|restart, compose down, launchctl, systemctl, pm2 and brew services commands that name one, or whose target listens on a protected port.
  • Every agent but Aider The governor works through the guard's hook. Aider runs no shell commands, so it starts no heavy jobs.
