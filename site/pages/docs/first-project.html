Setup is one screen.

  • What it found {{name}} looks at your computer first and shows, in order: GitHub (through gh), your projects, your agent, its model. Change any of it, then press Start {{name}}.
  • Projects Pick projects from your GitHub and your organisations (searchable, grouped by owner), or paste a URL. Untick any you don't want. {{w.setupPickLocal}} scans one folder you choose instead. Start opens once at least one is picked.
  • Project names A project with one repo takes the repo's name, and its issue keys follow it (Hello-World, HELLO-12). Several repos from one owner share one project, named after the owner.
  • Your agent Setup asks which AI you already pay for and picks the agent that comes with it.
  • Which one Claude Pro or Max: Claude Code. ChatGPT Plus or Pro: Codex. Gemini: Gemini CLI on a Gemini API key (free from Google AI Studio, kept in your secret store, passed as GEMINI_API_KEY). None of these: Claude Code on an Anthropic API key.
  • Missing one? {{w.setupAgentConnect}} shows the vendor's own install command and runs it in a terminal you can watch. Then it opens that agent's own sign-in.
  • The model Claude, a local model from a running Ollama, or a gateway URL. {{w.setupEdit}} opens the full form.
  • Every sign-in is your click {{name}} never asks you to paste a subscription token. More accounts sign in from Settings → Agents, in your browser, or for Claude Code with one command in your own terminal. See Agents and accounts.

Your checkout stays yours.

  • A copy you already have For each project, {{name}} looks for your own clone in ~/Code, ~/Projects, ~/Developer, ~/src, ~/GitHub and similar folders. It looks only for those projects and reads nothing but their git remotes.
  • Otherwise its own clone In ~/Overhand/projects/<owner> (projectsDir in the config). A checkout of yours uses its own code root.
  • Agents work beside it Each piece of work gets its own git worktree and branch, in the checkout's .claude/worktrees. .git/info/exclude keeps them out of git status. Your branch and uncommitted changes are left as they are.

Your first win, right away.

  • One small, safe task Straight after setup, {{name}} searches your projects on your computer, read-only and in under 30 seconds, for a check your own scripts report failing, a patch-level dependency upgrade, a README with no way to run the project, or a test for an untested pure function.
  • Old repos count A repo you just added is searched however long ago its last commit was.
  • An agent starts on it Now shows Your first win until its draft pull request is ready for you. On a phone it sits at the top of Now while it runs.
  • It ticks over The card shows the step the run has reached: {{w.winStepRead}}, {{w.winStepChange}}, {{w.winStepChecks}}, {{w.winStepPr}}. {{name}} reads them from the agent's own output, not a clock. What it last did is behind Details, and the header and {{w.viewCrew}} count it as an agent at work.
  • Set up tonight While it runs, three cards cover your first night: when the night report arrives ({{cfg.schedule.briefAtHour}}:00 unless you change it, on your phone too once ntfy is set up), what agents take tonight (the check-up's other findings and issues assigned to you, four at most, under the daily cap) and how far agents may go in the project. Each is one click to accept and stays editable in Settings.
  • Done looks done In green, with how long it took and what it cost ("about $0.30 of your plan", or "included in your plan"), how big the change is and its proof in one sentence, such as "The tests ran and passed." Review opens the change, its proof and screenshots when {{name}} took them, with {{w.reviewMarkReady}}, {{w.reviewRequestChanges}} and {{w.reviewClose}}.
  • Not offered twice Once the first win has a task, the check-up stops offering it.
  • Nothing else first Until that pull request opens, or the task fails, {{name}} starts no other agent run on its own: no plan of the day, no Slack inbox, no other work. What you ask for still runs.
  • Only what you added Needs you and the plan show pull requests from your projects, not the rest of your GitHub account.
  • Nothing in your tracker The first win never adds an issue anywhere.

Then give it work.

  • Two ways in {{w.workStory}} Both show in Work, and so do GitHub issues labelled agent. A project's tracker can be Linear or Jira instead.
  • When an agent asks It asks on the issue. Answer there, then label the issue again.
  • Plan the day On request, {{name}} gathers what's on your plate and proposes work; you queue what should start. To have it every morning, turn on {{w.setPlanOn}} in Settings → Advanced → Schedules and limits. It's off on a new install.
  • Standing work A project's view in {{w.viewCrew}} suggests project agents from its own work, each previewed before it starts.
  • Come back to pull requests They wait under Needs you, with any question an agent couldn't answer alone. Review opens the diff: {{w.reviewMarkReady}}, {{w.reviewRequestChanges}} (the agent's next round) or close it.
  • A careful start New projects start on {{modePropose}}. See Modes.
  • Only what you give it On a new install, agents take only the issues you give them, under a {{firstDayCap}} daily cap.

Connect your tools.

  • What already reaches them Setup and Settings → Connections show what reaches GitHub, Linear, Jira, Slack, Sentry and Vercel: the gh and vercel logins, stored tokens, and the MCP servers your agents are set up with (MCP, the Model Context Protocol, is how an agent reaches other tools).
  • Linear, Jira and Sentry {{w.connectButton}} signs {{name}} in to the service's official MCP server in your browser (a standard OAuth sign-in, no app to create). {{name}} then reads issues and errors through it, with no model in between. A stored API token still works.
  • Slack Its MCP server doesn't allow that sign-in. The Slack inbox reads through the servers listed in slack-mcp.json (Claude Code's --mcp-config format) in the config folder: ~/.overhand/slack-mcp.json, or the checkout's root when you run from source. It reads Slack on its schedule, and again when you come back to Overhand after {{freshMin}} minutes away; Needs you says when it last read. There is nothing to press, until a Slack sign-in expires: then Needs you says for which projects, and its button opens Claude Code where the inbox reads Slack. Type /mcp there and sign in.
  • Its path A slack-mcp.json left beside an installed binary moves to the config folder on the next start. Settings → Advanced → MCP and Slack mapping shows the full path.
  • Your own MCP servers Claude Code runs also get the ones in your ~/.claude.json.
  • The rest of Settings Projects, trackers (GitHub Issues, Linear, Jira), agent accounts and their models, project agents, schedule and budget, and your phone.
