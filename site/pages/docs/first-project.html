Setup is one screen.

  • What it found {{name}} looks at your computer first and shows, in order: GitHub (through gh), your projects, your agent, its model. Change any of it, then press Start {{name}}.
  • Projects Pick projects from your GitHub and your organisations (searchable, grouped by owner), or paste a URL. Untick any you don't want. {{w.setupPickLocal}} scans one folder you choose instead.
  • Your agent Setup asks which AI you already pay for and picks the agent that comes with it.
  • Which one Claude Pro or Max: Claude Code. ChatGPT Plus or Pro: Codex. Gemini: Gemini CLI on a Gemini API key (free from Google AI Studio, kept in your keychain, passed as GEMINI_API_KEY). None of these: Claude Code on an Anthropic API key.
  • Missing one? {{w.setupAgentConnect}} shows the vendor's own install command and runs it in a terminal you can watch. Then it opens that agent's own sign-in.
  • The model Claude, a local model from a running Ollama, or a gateway URL. {{w.setupEdit}} opens the full form.
  • Every sign-in is your click {{name}} never asks you to paste a subscription token. More accounts sign in from Settings → Agent accounts, in your browser, without a terminal. See Agents and accounts.

Your checkout stays yours.

  • A copy you already have For each project, {{name}} looks for your own clone in ~/Code, ~/Projects, ~/Developer, ~/src, ~/GitHub and similar folders. It looks only for those projects and reads nothing but their git remotes.
  • Otherwise its own clone In ~/Overhand/projects/<owner> (projectsDir in the config). A checkout of yours uses its own code root.
  • Agents work beside it Each piece of work gets its own git worktree and branch, in the checkout's .claude/worktrees. .git/info/exclude keeps them out of git status. Your branch and uncommitted changes are left as they are.

Your first win, right away.

  • One small, safe task Straight after setup, {{name}} searches your projects on your computer, read-only and in under 30 seconds, for a check your own scripts report failing, a patch-level dependency upgrade, a README with no way to run the project, or a test for an untested pure function.
  • An agent starts on it Now shows Your first win until its draft pull request is ready for you.
  • Nothing in your tracker The first win never adds a ticket anywhere.

Then give it work.

  • Label an issue Agents take GitHub issues labelled agent in a project's tracker. A project's tracker can be Linear or Jira instead.
  • When an agent asks It asks on the issue. Answer there, then label the issue again.
  • Plan the day {{name}} gathers what's on your plate and proposes work; you arm what should start.
  • Standing work A project's view in Crew suggests leads from its own work, each previewed before it starts.
  • Come back to pull requests They wait under Needs you, with any question an agent couldn't answer alone. Review opens the diff: mark it ready, ask for changes (the agent's next round) or close it.
  • A careful start New projects start on {{modePropose}}. See Modes.
  • Only what you label On a new install, agents take only the issues you label, under a {{firstDayCap}} daily cap.

Connect your tools.

  • What already reaches them Setup and Settings → Integrations show what reaches GitHub, Linear, Jira, Slack, Sentry and Vercel: the gh and vercel logins, stored tokens, and the MCP servers your agents are set up with (MCP, the Model Context Protocol, is how an agent reaches other tools).
  • Linear, Jira and Sentry {{w.connectButton}} signs {{name}} in to the service's official MCP server in your browser (a standard OAuth sign-in, no app to create). {{name}} then reads tickets and errors through it, with no model in between. A stored API token still works.
  • Slack Its MCP server doesn't allow that sign-in. The Slack inbox reads through the servers listed in slack-mcp.json (Claude Code's --mcp-config format) in the config folder: ~/.overhand/slack-mcp.json, or the checkout's root when you run from source. It reads Slack on its schedule, and again when you come back to Overhand after {{freshMin}} minutes away; Needs you says when it last read. There is nothing to press, until a Slack sign-in expires: then Needs you says for which projects, and its button opens Claude Code where the inbox reads Slack. Type /mcp there and sign in.
  • Its path A slack-mcp.json left beside an installed binary moves to the config folder on the next start. Settings → Integrations shows the full path.
  • Your own MCP servers Claude Code runs also get the ones in your ~/.claude.json.
  • The rest of Settings Projects, trackers (GitHub Issues, Linear, Jira), agent accounts and their models, leads, schedule and budget, and your phone.
