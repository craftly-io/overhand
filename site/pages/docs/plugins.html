Small add-ons, kept apart.

  • What one is A folder with a manifest and a script: a check (does your site answer?), a tracker (has the status page changed?) or a notifier. Each runs on its own schedule and reports findings.
  • Where you see them A finding marked bad or warn is a card in Needs you, with its fix as a button: open the page it names, or {{w.plRunAgain}}. Every finding, and each plugin's last run, is in Health under {{w.panePlugins}}.
  • Where you manage them Settings, Plugins: install, {{w.plApprove}}, {{w.plPause}} and {{w.plRemove}}. Each acts at once.
  • The kind Every kind runs the same way today: on its schedule, reporting findings. The kind is the label the app shows.

Installed from a pin you approve.

  • A pinned version The source is a git repository at one commit (all 40 characters), or a tarball checked against its SHA-256 before it's unpacked, from an https address or a full path on this computer. Overhand fetches it with none of your git config, so no hook, filter or saved login of yours runs, which also means a private repository needs a local copy.
  • The review {{pluginReview}}
  • Secrets A plugin names the secrets it wants. You grant each one by name when you approve it, and it reaches the plugin as an environment variable of that name, read from your secret store at each run.
  • Nothing else on its own A link or a special file in its folder stops the install, and so does a folder over 500 files or 10 MB.

What its sandbox enforces.

  • Enforced, not trusted {{pluginStops}}
  • Where it ends {{pluginLimit}}
  • The bridge At most 50 requests a run and 2 MB an answer, each within 15 seconds, never to a private or loopback address. Redirects come back to the plugin, so each hop is checked against its hosts again.

Write one.

  • The manifest overhand-plugin.json at the top of its folder: name, version, line (what it does, in one line), kind (check, tracker or notifier), entry (a .ts, .js or .mjs file), hosts, secrets, everyMin (15 to 1440, 60 if left out), timeoutSec (up to 120, 30 if left out) and memoryMb (64 to 1024, 256 if left out). A host is a public name such as status.example.com: no address, port or local name.
  • It runs on bun With plain fetch, which Overhand routes through the bridge. Packages aren't installed for it: ship what it needs in its folder.
  • It prints findings One JSON object per line: {"title": "…", "line": "…", "severity": "info" | "warn" | "bad", "fix": {"kind": "link", "url": "https://…"} | {"kind": "rerun"}}. Up to 50 a run. Any other line, or a non-zero exit, fails the run, and the app says why.
  • An example packages/core/plugins/site-answers checks that the hosts it declares answer, with tests for the sandbox beside it. Copy the folder, change its host and install it from your own repository.
