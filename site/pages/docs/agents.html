One account, one agent.

  • The agents {{name}} runs {{agents}}, each headless, the way its own command-line app runs.
  • An account Settings → Agents: which agent it runs, and the model behind it. Add as many as you have.
  • Kept apart Each account is used on its own; one person's work is never spread across several of their subscriptions.
  • One account per client After an account answers its test, {{w.scopeTitle}} picks the projects that run only on it (never on another account, even when it's busy) and the MCP servers it may use, from the ones in your agent's own config. Nothing secret is copied: the servers stay where they are.
  • Full sign-in, not a token {{w.claudeLoginNote}}
  • Remote MCP servers A remote server signs in once per account, because each account keeps its own logins. When a run finds one not signed in, Needs you says which, and its {{w.alMcpSignInGo}} button opens Claude Code in that account's folder with just those servers: type /mcp and sign in.
  • Models Claude, Amazon Bedrock, Google Vertex AI, or a gateway such as Ollama, LiteLLM or OpenRouter, including a model running on your own computer.

Sign-ins and API keys.

  • The agent's own sign-in In Settings → Agents, adding an account (or an account's sign-in button) runs that agent's own login for you: Codex in a folder kept for the account, Cursor Agent in the one login this computer has. {{w.signInBrowser}} opens its sign-in page on the device you're on, your phone too. {{name}} shows {{w.signInDone}} once the agent's own status check says so, then makes a test call.
  • Claude Code, in your own terminal A Claude account signs in through Anthropic's own flow, which Anthropic's terms require, so {{name}} never runs it or takes its code. The card shows the exact command for that account's folder, CLAUDE_CONFIG_DIR=… claude auth login, with {{w.hostedCopy}}: {{w.signInYourTerminal}} On a phone it says: {{w.signInOnComputer}}
  • From another device Codex's usual sign-in calls back to the computer it runs on, so from a phone or over Access from anywhere it uses Codex's device code instead: the app shows the code to enter on the sign-in page.
  • What {{name}} reads Only the sign-in link (and a code to show) from what the agent prints, and for Claude Code only whether claude auth status says it's signed in. Nothing it prints is logged or kept. A sign-in still waiting after 10 minutes is stopped.
  • Only your own accounts {{w.addAccountYours}} A client's account is a key the client made for you, never their plan's login.
  • OpenCode It signs in to a provider, once per computer. In the app, {{w.addAccountWith}} runs a provider account's sign-in with a code to enter (ChatGPT), and {{w.addAccountProviderKey}} takes a provider's key (Anthropic, OpenAI, OpenRouter, Google, Groq, DeepSeek, Mistral or xAI) and types it into OpenCode's own sign-in for you. The key goes to OpenCode only; {{name}} keeps no copy.
  • Already signed in A sign-in already on this computer is reused, and so is GitHub through gh.
  • Your own sign-in, under the OS sandbox An account still on the sign-in you had before {{name}} can't run where the OS sandbox is on: runs can't reach your own agent config. Such an account is passed over, as one at its usage limit is, and Needs you shows a card to sign it in once, with its sign-in button. Once it's signed in in its own folder, it runs again.
  • An API key Stored in your secret store, named after its account: anthropic-key-<account>, codex-key-<account>, gemini-key-<account> or cursor-key-<account>. Gemini CLI runs on a Gemini API key. {{w.setupGeminiKeyData}} ({{w.setupGeminiTerms}})
  • Never a subscription token {{name}} doesn't ask for, store or pass on the token behind a Claude plan.

How each account is paid for.

  • Plan A flat subscription such as a Claude or ChatGPT plan. Its runs cost nothing extra and follow the plan's usage limits.
  • Pay-per-use Charged per token: an API key, or a paid gateway.
  • Cloud Charged to your own cloud bill, as with Bedrock or Vertex AI.
  • Local A model on your own computer: no charge.
  • Out of usage When an account's agent says it has hit a usage limit, tasks, project agents and tests all skip that account until the reset the message names, and Settings says so on the account. Only the agent's own result and its limit events count: a project's test that prints "429" or "rate limit" is an ordinary failure. A task that waits uses no attempt, but each second time in a row its own run stops at the limit counts as one, so it can't rerun forever. While every account waits, the dashboard says when work resumes.
  • Signed out When an account's agent says its sign-in has expired, the task waits instead of failing, the account is passed over, and Needs you shows the same Sign in card. Once it's signed in again, or its Test answers, its runs go on.
  • How it knows From the way the account signs in: claude auth status names a Claude subscription. When it can't tell, Needs you asks, and Settings lets you change it.

The model behind each account.

  • Who uses what Claude Code uses every backend below. Codex, OpenCode and Aider use a gateway's URL and model.
  • Claude, by its own sign-in Each account gets its own Claude Code config folder, agent-home/accounts/<account> in the config folder. Signing in runs claude auth login with CLAUDE_CONFIG_DIR set to it, through Anthropic's own flow.
  • Where that login lives Claude Code keeps it: an item in the secret store tied to that folder on macOS, .credentials.json inside it on Linux. {{name}} never reads, stores or passes it on, and runs that account's agents with CLAUDE_CONFIG_DIR pointing there.
  • Your own plan Usage counts against your Claude plan. {{w.planUseNote}} ({{w.planUseTerms}}) Only Claude accounts show 5-hour and weekly usage.
  • Paced through the week {{w.quickPace}} is on unless you turn it off: an account that has used more of its week than has passed waits until the week catches up. Only plan accounts have a week to pace; an API key never waits for one.
  • No setup token {{name}} never asks for, stores or routes a token from claude setup-token, as Anthropic's terms require.
  • Claude, by API key A key from platform.claude.com, stored as anthropic-key-<account> and passed as ANTHROPIC_API_KEY. Billed per use to your Anthropic account, under its Commercial Terms.
  • Amazon Bedrock CLAUDE_CODE_USE_BEDROCK=1 with the region (and optional AWS profile) you set. Credentials come from this machine's AWS credential chain.
  • Google Vertex AI CLAUDE_CODE_USE_VERTEX=1, CLOUD_ML_REGION and ANTHROPIC_VERTEX_PROJECT_ID. Credentials come from gcloud's Application Default Credentials.
  • A gateway Any Anthropic-compatible endpoint through ANTHROPIC_BASE_URL, with ANTHROPIC_AUTH_TOKEN from a secret store item you name, or a placeholder for local servers that take any token. Presets for Ollama, LiteLLM and OpenRouter; tested end to end with Ollama and qwen3:1.7b.
  • One model for every run A model set on a Bedrock, Vertex or gateway account becomes ANTHROPIC_MODEL and pins the opus, sonnet and haiku aliases. A separate small model sets ANTHROPIC_DEFAULT_HAIKU_MODEL.
  • Checked overhand doctor reports a gateway that doesn't answer.
  • Claude Code's own docs Bedrock, Vertex AI and LLM gateways.
